# Permission-to-quote requests

Two sources are the ceiling on answer quality, and neither is a coverage
problem — both are already indexed. They publish no licence, so the site can
name and link them but never quote them, which is why answers about them are
thinner than answers about Game Manual 0.

Pedro Pathing is the single most asked-about topic in the query log.

Send these from a team address. Nothing needs changing except the bracketed
parts.

---

## 1. Pedro Pathing

**To:** the maintainers via https://github.com/Pedro-Pathing/PedroPathing/issues
(open an issue titled "Permission to quote the docs in an FTC search tool")

> Hi — we're [team number], Sharp Face Robotics. We built a free, non-commercial
> search tool that answers FTC questions from indexed documentation and shows
> the source page behind every claim: https://sharpftc.pages.dev
>
> Pedro Pathing is the most asked-about topic on it by a wide margin. Right now
> we only summarise your docs in our own words and link out, because the docs
> site doesn't publish a licence and we didn't want to assume. That works, but
> it means we can't quote you accurately — and on tuning questions especially,
> the exact wording matters.
>
> Would you be willing to let us quote short excerpts from the documentation,
> with attribution and a link back to the page each one came from? Something as
> simple as "yes, with attribution" in reply is enough for us, or we're happy to
> work to whatever terms you'd prefer. Adding a licence file to the docs repo
> would also settle it for everyone else building on your work.
>
> The site carries no advertising and never will — it indexes Game Manual 0,
> which is CC BY-NC, so commercial use is off the table permanently.
>
> Thanks for Pedro Pathing. It's what most teams around us are running.

## If they say no, or don't reply

Nothing breaks. Both stay exactly as they are — named, linked, never quoted —
which is the correct default when no licence is published. Don't assume silence
is permission.
